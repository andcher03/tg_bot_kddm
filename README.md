# Бот Молодёжь Казани

**Бот Молодёжь Казани** — Telegram-бот и веб-панель администрирования для молодёжной информационной платформы Казани.

Цель проекта — собрать в одном месте актуальные мероприятия, полезные городские сервисы, возможности для студентов и инструменты взаимодействия с молодёжной аудиторией.

Проект состоит из двух основных частей:

- **Telegram-бот** — пользовательский интерфейс;
- **Web Admin** — административная панель для управления данными.

Обе части работают с общей базой данных **PostgreSQL**.

---

## Возможности

### Telegram-бот

- доступ к основному меню без обязательной регистрации;
- регистрация пользователя через Telegram;
- автоматическое сохранение Telegram ID, username и имени;
- присвоение пользователю публичного идентификатора вида `KZN-000001`;
- выбор и изменение ВУЗа;
- раздел **«Мой профиль»**;
- афиша актуальных мероприятий;
- поиск мероприятий по параметрам;
- регистрация на мероприятия;
- раздел **«Мои события»**;
- оценки и отзывы после мероприятий;
- пользовательские подписки на рассылки;
- молодёжная карта Казани;
- информационные разделы для студентов и молодёжи города.

Основные разделы Telegram-бота:

```text
👤 Мой профиль
🎭 Афиша
🗺 Молодёжная карта Казани
🏙 Переехавшим в Казань
👥 Чем занимается молодёжь в Казани
🎓 Поддержка и льготы
🏆 Гранты и конкурсы для студентов
```

## Веб-панель администратора

Web Admin реализован на **FastAPI + Jinja2**.

Основные разделы:

```text
Главная
Пользователи
Мероприятия
Регистрации
Отзывы
Рассылка
```

### Пользователи

Администратор может:

- просматривать зарегистрированных пользователей;
- искать пользователей по:
  - KZN ID;
  - имени;
  - ВУЗу;
  - Telegram ID;
  - username;
- открывать карточку конкретного пользователя.

### Мероприятия

Администратор может:

- создавать новые мероприятия;
- редактировать существующие;
- просматривать карточку мероприятия;
- видеть список участников;
- видеть количество регистраций;
- просматривать среднюю оценку;
- читать отзывы;
- переносить мероприятие в архив;
- возвращать мероприятие из архива обратно в публикацию.

Мероприятия имеют публичные идентификаторы:

```text
EVENT-000001
EVENT-000002
EVENT-000003
```

Основные статусы:

```text
active
archived
```

При архивировании мероприятие **не удаляется**. Все связанные регистрации, участники и отзывы сохраняются.

### Регистрации

В административной панели доступен общий список регистраций пользователей на мероприятия.

Поддерживается:

- фильтрация по мероприятию;
- поиск по пользователю;
- отображение KZN ID;
- отображение ВУЗа;
- дата регистрации;
- статус регистрации;
- переход в карточку пользователя;
- переход в карточку мероприятия.

### Отзывы

Администратор может:

- просматривать все отзывы;
- фильтровать отзывы по мероприятию;
- видеть среднюю оценку;
- видеть количество отзывов;
- переходить в профиль пользователя.

### Рассылки

Административная панель позволяет формировать Telegram-рассылки.

Доступные варианты аудитории:

- все зарегистрированные пользователи;
- пользователи выбранных ВУЗов;
- участники выбранных мероприятий;
- объединение нескольких сегментов без дублирования получателей.

Поддерживаемые ВУЗы:

```text
КФУ
КНИТУ-КАИ
КНИТУ
КГЭУ
КГАСУ
КазГМУ
Университет управления ТИСБИ
Другой ВУЗ
```

В рассылку можно добавить:

- текст;
- фотографию.

Перед отправкой администратор может:

- сформировать аудиторию;
- увидеть количество получателей;
- посмотреть список получателей;
- проверить изображение;
- подтвердить отправку.

## База данных

Схема PostgreSQL управляется через Alembic. Для новой базы выполните:

```bash
python -m alembic upgrade head
```

Команда создаёт основные таблицы бота, Web Admin, историю рассылок и
таблицы статистики Telegram-канала.

Если база уже существовала до добавления Alembic, сначала сделайте резервную
копию и сравните её схему с начальной миграцией. Не запускайте начальную
миграцию поверх существующих таблиц. После проверки совместимости отметьте
схему как применённую:

```bash
python -m alembic stamp 20260820_0001
```

Основные таблицы проекта:

```text
users
events
registrations
event_reviews
mailing_lists
mailing_subscriptions
settings
```

### `users`

Содержит данные зарегистрированных пользователей:

- внутренний ID;
- `KZN-XXXXXX`;
- Telegram ID;
- username;
- имя;
- ВУЗ;
- роль;
- дату регистрации.

### `events`

Содержит данные мероприятий:

- внутренний ID;
- `EVENT-XXXXXX`;
- название;
- описание;
- дату;
- время;
- место;
- категорию;
- статус;
- параметры поиска и фильтрации.

### `registrations`

Связывает пользователей и мероприятия.

### `event_reviews`

Хранит:

- пользователя;
- мероприятие;
- оценку от 1 до 5;
- текст отзыва;
- дату создания.

### `mailing_lists` и `mailing_subscriptions`

Используются для пользовательских подписок на тематические рассылки.

Административные массовые рассылки рассматриваются отдельно от добровольных пользовательских подписок.

## Запуск Telegram-бота

Создайте виртуальное окружение и установите зафиксированные зависимости:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m alembic upgrade head
```

Активируйте виртуальное окружение и запустите:

```bash
python bot.py
```

---

## Запуск Web Admin

Из корня проекта:

```bash
python -m uvicorn web_admin.app:app --reload --host 127.0.0.1 --port 8000
```

После запуска административная панель доступна по адресу:

```text
http://127.0.0.1:8000
```

## Переменные окружения

Проект использует `.env` для конфиденциальных параметров.

Пример:

```env
BOT_TOKEN=your_telegram_bot_token
DATABASE_URL=postgresql+asyncpg://user@localhost:5432/database_name
TELEGRAM_CHANNEL_ID=-1001234567890
```

Файл `.env` не должен попадать в GitHub.

Создайте его из безопасного шаблона `.env.example`. Правила `.gitignore`
уже исключают локальные и production-варианты файла.

### Миграции PostgreSQL

Структурой базы управляет только Alembic. Бот и Web Admin не создают таблицы
во время запуска.

Перед обновлением production-базы сначала создайте резервную копию, затем
проверьте и примените миграции:

```bash
python -m alembic current
python -m alembic upgrade head
python -m alembic check
```

Для новой пустой базы достаточно `python -m alembic upgrade head`. Команду
`alembic stamp` нельзя использовать вместо миграций: она допустима только для
однократной регистрации заранее проверенной существующей схемы.

### Тесты

Тестовые зависимости устанавливаются отдельно:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Проверки, которым нужна PostgreSQL, запускаются только при наличии отдельной
тестовой базы:

```env
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost:5432/kddm_test
```

`TEST_DATABASE_URL` не может указывать на ту же базу, что и `DATABASE_URL`.
Изменения интеграционного теста выполняются в транзакции и откатываются.

## Безопасность

Перед публичным развёртыванием Web Admin необходимо:

- добавить авторизацию администратора;
- закрыть административные маршруты от публичного доступа;
- использовать HTTPS;
- хранить токены и данные подключения к БД только в переменных окружения;
- не публиковать `.env` и другие секреты в репозитории.
